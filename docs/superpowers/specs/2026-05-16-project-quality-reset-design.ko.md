# 프로젝트 품질 리셋 설계

## 상태 스냅샷

2026-05-25 현재 저장소 상태를 기준으로 갱신했다.

첫 번째 품질 리셋 작업으로 테스트와 문서 기반은 이미 어느 정도 들어와 있다. 그래서 이 문서는 더 이상 Phase 1 제안서만이 아니라, 현재 제품 기능, 현재 엔지니어링 구조, 그리고 봇의 캐릭터 경험을 깨뜨리지 않기 위해 다음에 해야 할 품질 리셋 작업을 함께 기록한다.

Firefly는 캐릭터 대화, 로컬 사용자 기억, 방 맥락, 호감도, 명령어 기반 자동 실행, 투표, 일일 최신 소식, 통화 기록, 전사 요약, 전사 검색을 제공하는 Python Discord 봇이다.

가장 중요한 런타임 자산은 여전히 프롬프트 파일과 메모리 파일이다. `prompt.txt`, `prompt_special.txt`, `prompt_commands_general.txt`, `prompt_commands_special.txt`, `prompt_news.txt`, `memory.json`, `data/`는 단순 캐시가 아니라 동작을 정의하는 상태로 다룬다.

## 목적

핵심 캐릭터 경험을 유지하면서 유지보수성, 안정성, 확장성, 운영 명확성을 높인다.

가장 높은 우선순위는 대화, 기억, 프롬프트, 호감도, 방 맥락 경로를 보호하는 것이다. 리팩터링은 영향을 받는 동작이 테스트로 보호되어 있거나, 먼저 작고 검토 가능한 방식으로 현재 동작을 특성화할 수 있을 때만 진행한다.

## 목표

- 현재 사용자-facing 봇 동작을 유지한다. 특히 대화, 기억, 호감도, 프롬프트 선택, 방 맥락, 자동 명령 실행을 보호한다.
- 텍스트 명령어와 슬래시 명령어를 계속 일치시킨다.
- 모델이 명령 실행 여부를 판단할 때 사용하는 프롬프트 명령어 가이드를 정확하게 유지한다.
- 순수 로직, 파일 기반 상태, 명령어 파싱에 대한 빠른 테스트를 늘린다.
- 큰 모듈은 해당 동작의 테스트가 생긴 뒤 점진적으로 나눈다.
- 로컬 설정, 필수 환경 변수, 데이터 경로, 명령어 목록, 배포 엔트리포인트, 운영 메모를 문서화한다.
- 함수, 모듈, 인터페이스를 추가하거나 바꿀 때 가벼운 SOLID 원칙을 따른다.

## 비목표

- 봇 프레임워크를 다시 쓰거나 `discord.py`를 교체하지 않는다.
- 기계적인 정리 과정에서 봇 페르소나, 프롬프트 내용, 특별 사용자 의미, 메모리 의미를 바꾸지 않는다.
- 전사, 기록 저장, 요약, 검색 동작이 특성화되기 전에 통화 기록 구조를 크게 다시 설계하지 않는다.
- 작은 함수와 좁은 모듈로 충분한 곳에 큰 클래스 계층을 만들지 않는다.
- 동작 보존 계획과 테스트 없이 큰 기능 모듈을 한 번에 이동하지 않는다.

## 현재 제품 기능

### 대화와 기억

- `Firefly.py`와 `firefly/commands.py`를 통한 멘션 기반 캐릭터 채팅.
- 이름, 호칭, 호감도, 마지막 대화 시각, 최근 히스토리를 가진 사용자별 기억.
- 특별 사용자에 대한 고정 호감도와 호칭 의미.
- `__rooms__` 아래에 저장되는 방 기억. 인터넷 모드, 단체 모드, 방 히스토리를 포함한다.
- 최근 참여자, 호칭, 호감도, 방 메시지를 포함하는 단체 모드 프롬프트 맥락.
- 장기 미접속, 기념일 비슷한 순간, 최근 주제에 대한 관계/이벤트 힌트.
- `firefly/content.py`를 통한 긴 고정 응답 지원.

### 명령어 표면

- 일반 명령어: `/도움말`, `/호감도`, `/초기화`, `/호칭`, `/프로필`, `/주사위`, `/팀나누기`, `/실행`, `/요약`, `/최신소식`, `/주제 목록`.
- 특별 사용자 명령어: `/기록`, `/기록중지`, `/대화목록`, `/기록검색`, `/녹음검색`, `/투표`, `/투표마감`, `/인터넷모드`, `/단체모드`, `/방상태`, `/방기억`, `/방초기화`, `/봇상태`, `/관리상태`, `/메모리파일`, 메모리 초기화 명령, 유저 정보 명령, 호감도 관리 명령, 최신 소식 시간 명령, 최신 소식 중복 기록 초기화 명령, 주제 관리 명령.
- 전체 명령어 세트에 대해 슬래시 명령어가 등록되어 있고, 가능한 경우 같은 명령 핸들러 경로로 라우팅된다.
- 프롬프트 명령어 가이드는 모델에게 언제 명령어 한 줄을 출력해야 하는지, 언제 명령 결과를 반영하는 `/실행`을 써야 하는지 알려준다.
- `/실행`은 허용된 명령어를 먼저 실행하고, 보이는 결과를 캡처한 뒤, 그 결과를 맥락으로 모델 답변을 만든다.

### 유틸리티 명령

- `/프로필 [@유저]`는 아바타, 이름, 호칭, 호감도 단계, 마지막 대화 시각을 보여준다.
- `/주사위 [시작] [끝]`은 숫자 하나 또는 두 개로 범위를 해석하고 범위 검증을 한다.
- `/팀나누기`는 팀 수 기준과 팀당 인원 기준을 모두 지원한다.
- 유틸리티 명령의 파싱과 포맷팅은 `firefly/utility_commands.py`에 있다.

### 투표

- 투표 생성은 명시적 항목 수, 2개에서 10개까지의 선택지, 유연한 마감 시간, 임베드, 리액션 선택지, 진행 중 투표 저장, 시작 시 카운트다운 복원, 수동 마감, 결과 임베드, 단일 투표 강제를 지원한다.
- 투표 프롬프트 가이드는 설명을 투표 항목 안에 넣지 않도록 하고, 사용자가 투표와 후속 답변을 함께 원하면 `/실행 /투표 ... || 프롬프트`를 쓰도록 안내한다.

### 일일 최신 소식

- 일일 최신 소식은 KST 기준 시간으로 예약되고 `__daily_news__` 아래에 저장된다.
- 사용자는 구독하거나 구독 해제할 수 있고, 특별 사용자는 다른 사용자를 관리할 수 있다.
- 주제는 목록 조회, 추가, 제거, 설정, 변경이 가능하다.
- 전달은 OpenAI 웹 검색, 뉴스 프롬프트, 전달 윈도우, 중복 추적, URL 정규화, 전달 항목 정리/초기화 명령을 사용한다.

### 통화 기록과 검색

- 특별 사용자는 통화 기록을 시작하고 중지할 수 있다.
- 기록은 `data/voice_records/records/` 아래 JSONL 파일로 저장되고 `index.json`으로 인덱싱된다.
- 통화 기록 보존 기간은 설정 가능하며 시작 시와 주기적 정리 루프에서 만료 기록을 삭제한다.
- 기록 참조는 파일명 또는 `1번`, `#1`, `index:1` 같은 목록 번호를 사용할 수 있다.
- 통화 요약은 최근 기록, 파일명, 인덱스 기록을 대상으로 할 수 있다.
- 통화 검색은 특정 기록 또는 최근 기록들을 대상으로 검색하고, 관련 전사와 앞뒤 맥락을 선택한 뒤 모델 도움으로 답을 요약한다.
- 기존 별칭 `/녹음검색`과 새 별칭 `/기록검색`은 모두 같은 통화 검색 흐름으로 라우팅된다.

### 운영과 관리자 도구

- `/봇상태`와 `/관리상태`는 사용자 수, 방 수, 방 메시지 수, 활성 투표 수, 최신 소식 구독자 수, 최신 소식 주제 수, 저장된 통화 기록 수, 현재 녹음 여부, 현재 방 모드 상태를 보여준다.
- `/메모리파일`은 특별 사용자에게 `memory.json` 또는 저장된 통화 기록 JSONL 파일을 보낼 수 있다.
- 메모리 초기화 명령은 명시적인 `확인`이 필요하다.
- `.env.example`은 필수 비밀값과 선택 경로, 프롬프트, 통화 기록, 보존 기간 설정을 문서화한다.
- `README.md`는 설정, 데이터 경로, 추가 명령어, 배포, 검증 명령을 문서화한다.

## 현재 엔지니어링 구조

- `Firefly.py`는 Discord 엔트리포인트다. 클라이언트 설정, 슬래시 명령 등록, 최상위 이벤트, 뉴스 시작, 투표 복원, 통화 기록 정리 루프를 담당한다.
- `firefly/commands.py`는 여전히 텍스트 명령의 주요 오케스트레이터다. 명령 라우팅, 특별 사용자 게이트, 명령 어댑터 캡처, 요약, 메모리 파일 전송, 방 모드, 일반 대화 fallback을 조율한다.
- `firefly/commands_parser.py`는 순수 명령어 경계와 요약 인자 파싱 헬퍼를 담는다.
- `firefly/command_registry.py`는 새로 추가된 특별 사용자 전용 명령 prefix를 위한 텍스트 명령 스펙을 정의한다.
- `firefly/utility_commands.py`는 주사위, 팀 나누기, 명령 어댑터의 순수 파싱과 포맷팅을 담는다.
- `firefly/storage.py`는 스레드 안전 JSON 메모리 읽기/쓰기, 정규화, 방 상태, 히스토리 자르기를 담당한다.
- `firefly/prompts.py`는 기본 시스템 프롬프트, 명령어 가이드 삽입, 모델 히스토리, 방 모델 히스토리를 만든다.
- `firefly/relationship_events.py`는 이벤트 상태를 사용자 데이터에 유지하면서 가벼운 관계 맥락을 만든다.
- `firefly/ai.py`는 채팅, 대화 요약, 통화 요약, 통화 검색 요약, 일일 최신 소식 요약을 위한 OpenAI 호출을 담당한다.
- `firefly/news.py`는 뉴스 설정, 명령 처리, 중복 제거, 스케줄링, 전달을 담당한다. 아직 큰 리팩터링 후보이다.
- `firefly/voice.py`는 Discord 음성 수신, 실시간 전사, fallback 전사, 활성 녹음 생명주기, 연결 해제 처리를 담당한다. 아직 큰 리팩터링 후보이다.
- `firefly/voice_records.py`는 통화 기록 JSONL/index 저장, 보존 기간, 목록, 참조 해석, 전사 읽기를 담당한다.
- `firefly/voice_search.py`는 통화 검색 인자 파싱, 전사 선택, 맥락 포맷팅을 담당한다.
- `firefly/polls.py`는 투표 파싱, 임베드, 저장, 스케줄링, 집계, 마감, 단일 투표 강제를 담당한다.
- `firefly/embeds.py`는 도움말, 프로필, 방 기억, 유저 정보, 요약 임베드를 담당한다.
- `firefly/admin_status.py`는 순수 상태 텍스트 생성을 담당한다.

## 보호해야 할 데이터 흐름

### 멘션 채팅 흐름

1. `Firefly.py`가 Discord 메시지를 받는다.
2. `text_utils.clean_discord_content()`가 내용을 정규화하고 멘션을 바꾸거나 제거한다.
3. 멘션된 메시지는 `storage.py`를 통해 방/사용자 상태를 불러온다.
4. `commands.handle_mentioned_message()`가 명령어, 특별 사용자 명령어, 유틸 명령, 요약, 일반 대화 fallback을 라우팅한다.
5. 일반 대화는 `ai.generate_reply()`를 호출한다.
6. `ai.generate_reply()`는 호감도를 조정하고, 관계 힌트를 만들고, 시스템 프롬프트를 만들고, 단체 모드이면 방 맥락을 추가하고, 인터넷 모드이면 웹 검색 모델을 선택한다.
7. OpenAI가 답변을 반환한다.
8. 한 줄짜리 명령어 답변은 `_run_auto_command_from_reply()`로 자동 실행될 수 있다.
9. 사용자/방 히스토리를 갱신한 뒤 Discord에 응답을 보낸다.

### 슬래시 명령 흐름

1. `Firefly.py`가 슬래시 interaction을 받는다.
2. 슬래시 핸들러가 텍스트 명령 입력과 `_SlashMessage` 어댑터를 만든다.
3. 대부분의 슬래시 명령은 `_run_text_command_slash()`를 호출한다.
4. `_run_text_command_slash()`는 텍스트 명령과 같은 방/사용자 상태를 불러온다.
5. `commands.handle_mentioned_message()`가 공유 명령 경로로 동작을 처리한다.

### 명령 어댑터 흐름

1. 모델 또는 사용자가 `/실행 command | prompt` 또는 `/실행 command || prompt`를 호출한다.
2. `utility_commands.parse_command_adapter_args()`가 실행할 명령과 후속 프롬프트를 분리한다.
3. 파괴적이거나 reset 계열인 차단 명령은 어댑터 안에서 거부된다.
4. 명령은 캡처 채널을 통해 일반 명령 핸들러로 실행된다.
5. 캡처된 표시 결과가 extra context로 `ai.generate_reply()`에 전달된다.

### 통화 기록 흐름

1. 특별 사용자가 `/기록`으로 기록을 시작한다.
2. `voice.py`가 통화방에 연결하고 실시간 전사/fallback 전사를 관리한다.
3. `voice_records.py`가 metadata, event, transcript item을 JSONL에 append한다.
4. `/대화목록`은 index를 읽어 최근 기록을 표시한다.
5. `/요약`, `/기록검색`, `/녹음검색`, `/메모리파일`은 `voice_records.py`를 통해 파일명 또는 인덱스를 해석한다.
6. `voice_search.py`가 관련 전사 맥락을 선택한다.
7. `ai.py`가 모델 도움으로 요약하거나 답한다.

### 최신 소식 흐름

1. 최신 소식 설정은 `__daily_news__` 아래에 저장된다.
2. `start_daily_news_task()`가 KST 발송 시간을 기준으로 전달을 예약한다.
3. `generate_daily_news_digest()`가 뉴스 프롬프트와 웹 검색 모델을 사용한다.
4. 전달된 URL과 리포트 항목을 정규화하고 추적해 중복을 줄인다.
5. 구독자에게 개인 메시지를 보낸다.

### 투표 흐름

1. `/투표`가 투표 spec을 파싱하고 임베드를 올린다.
2. 투표 상태는 `__polls__` 아래에 저장된다.
3. 리액션 핸들러가 집계를 갱신하고 사용자당 한 표를 강제한다.
4. 시작 시 진행 중인 투표 타이머를 복원한다.
5. 타이머 만료 또는 `/투표마감`이 투표를 마감하고 활성 상태를 제거한다.

## SOLID 가이드

SOLID는 Python답고 가볍게 적용한다.

- Single Responsibility: 파싱, 포맷팅, 저장, 외부 API 호출, Discord 전송을 가능한 한 분리한다.
- Open/Closed: 새 명령군은 하나의 큰 조건문을 계속 늘리기보다 parser/registry/handler 단위로 추가한다.
- Liskov Substitution: 테스트가 Discord/OpenAI 협력자를 fake로 바꿀 수 있도록 헬퍼 시그니처를 안정적으로 유지한다.
- Interface Segregation: 함수가 필요한 데이터만 넘긴다. 순수 로직에는 전체 Discord 객체보다 작은 값이나 dict를 선호한다.
- Dependency Inversion: 가능한 경우 순수 로직은 Discord, OpenAI, 파일 시스템 경로, 전역 config에서 독립시킨다.

이 가이드는 클래스가 많은 구조를 만들자는 뜻이 아니다. 기본값은 작은 함수, 좁은 모듈, 명시적 의존성, 동작 중심 테스트다.

## 테스트 전략

빠른 로컬 검증에는 `pytest`를 사용한다.

현재 기대하는 체크:

```powershell
python -m compileall Firefly.py firefly
python -m pytest
```

향후 테스트 규칙:

- 순수 함수 테스트는 Discord client를 만들지 않는다.
- 파일 기반 테스트는 임시 경로를 사용하고 실제 `data/` 또는 `memory.json`을 건드리지 않는다.
- 테스트는 실제 Discord 또는 OpenAI 자격 증명을 요구하지 않는다.
- 프롬프트 동작 테스트는 전체 문장보다 구조와 삽입된 명령어 가이드 내용을 확인한다. 단, 정확한 문구가 의도된 동작이면 예외다.
- integration-heavy 동작은 live Discord/OpenAI 테스트 전에 좁은 fake를 우선 사용한다.

## 리스크 기록

- `commands.py`는 아직 변경이 자주 몰리는 오케스트레이션 hotspot이다.
- `news.py`와 `voice.py`는 아직 크고 여러 책임이 섞여 있다.
- 프롬프트 명령어 가이드는 동작을 정의하므로 Python 코드가 그대로여도 봇 동작을 바꿀 수 있다.
- 텍스트 명령과 슬래시 명령은 한쪽만 바꾸면 drift가 생길 수 있다.
- 메모리 schema 변경은 기존 로컬 런타임 상태를 깨뜨릴 수 있다.
- 통화 JSONL/index 호환성은 중요하다. 오래된 기록도 인덱스나 파일명으로 참조될 수 있다.
- 최신 소식 중복 추적은 URL 정규화와 digest 포맷에 의존한다.

## 다음 품질 패스의 승인 기준

- `python -m compileall Firefly.py firefly`가 통과한다.
- `python -m pytest`가 실제 Discord 또는 OpenAI 자격 증명 없이 통과한다.
- 이동한 동작에는 이동 전 또는 이동과 함께 테스트가 있다.
- 변경된 명령어는 텍스트 명령과 슬래시 명령이 계속 일치한다.
- 프롬프트 가이드 변경은 동작 변경으로 보고 의도적으로 검토한다.
- `commands.py`, `news.py`, `voice.py`, `polls.py` 리팩터링은 동작 영역별로 검토 가능한 크기로 유지한다.
- `README.md`와 이 설계 문서는 실제 배포된 명령어 표면과 동기화되어 있다.
