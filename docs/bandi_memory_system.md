# 반디 기억 시스템

이 문서는 반디의 사용자 기억 구조와 운영 명령을 설명한다.

## 구조

사용자별 기억은 대화 메모리 JSON의 사용자 레코드에 저장된다. 기존 `brain_notes`는 호환을 위해 유지하지만, 실제 판단 기준은 아래 구조를 사용한다.

```json
{
  "123456789012345": {
    "short_term_memory": [],
    "long_term_memory": [],
    "memory_stats": {},
    "brain_notes": []
  }
}
```

각 기억 항목은 다음 필드를 가진다.

- `memory_id`: 기억 항목 고유 ID
- `memory_type`: `short_term` 또는 `long_term`
- `content`: 기억 내용
- `importance_score`: 중요도 점수, 0.0에서 1.0
- `frequency_score`: 반복 등장 횟수
- `memory_category`: `relationship`, `preference`, `project`, `general` 중 하나
- `affective_score`: 반디가 느끼는 정서 방향, -1.0에서 1.0
- `distance_score`: 반디가 둘 거리감, 0.0은 가까움, 1.0은 경계/거리둠
- `emotional_intensity_score`: 감정 변화 강도, 0.0에서 1.0
- `created_at`: 생성 시각
- `updated_at`: 마지막 수정 시각
- `last_used_at`: 마지막 참조 또는 갱신 시각

장기 기억은 추가로 `promotion_reason`, `promoted_at`을 가진다.

## 단기 기억

단기 기억은 최근 대화에서 기억할 가치가 있어 보이는 후보를 임시 보관한다. `/뇌추가` 명령은 곧바로 장기 기억을 만들지 않고 단기 기억 후보를 추가한다.

단기 기억 후보 예시:

- 반디가 그 사람에게 신뢰, 편안함, 경계, 불편함을 느끼게 만든 사건
- 반디가 그 사람과 어느 정도 거리감을 둬야 할지 판단하는 데 필요한 관찰
- 배려, 존중, 무례, 공격성, 사과, 관계 회복 같은 관계 신호
- 사용자의 취향
- 자주 언급하는 관심사
- 프로젝트 정보
- 반복되는 요청 패턴
- 선호하는 응답 방식

단기 기억은 최대 개수와 보존 기간이 있으며, 오래되거나 초과된 항목은 정리된다.

## 장기 기억

장기 기억은 지속적으로 보존해 반디의 태도와 응답 방식에 반영할 기억이다.

승격 기준:

- 같은 기억 후보가 여러 번 반복 등장
- 중요도 점수가 높음
- 신뢰, 경계, 거리감처럼 반디의 태도에 직접 영향을 주는 관계 변화
- 향후 대화에 영향을 줄 가능성이 높음
- 장기적 선호, 금기, 작업 방식, 감정적 반응 패턴에 해당

사용자에 대한 기억이 거의 없으면 관계 기억은 더 빠르게 축적된다. 관계 후보가 2회 반복되면 장기 기억으로 승격될 수 있다.

이미 기억이 많은 사용자는 더 천천히 업데이트한다. 일반 반복 기준은 높아지고, 강한 신뢰 변화나 경계해야 할 급격한 변화처럼 감정 강도가 큰 경우에만 빠르게 승격된다.

단발성 일정, 방금 끝난 요청, 단순 농담, 오늘만 필요한 정보는 장기 기억으로 승격하지 않는다.

## 명령어

관리 권한이 있는 사용자는 다음 명령을 사용할 수 있다.

- `/뇌 @유저`: 단기 기억 후보와 장기 기억을 함께 조회
- `/뇌추가 @유저 [기억후보]`: 단기 기억 후보 추가
- `/뇌추가 @유저 중요도=높음 [기억후보]`: 높은 중요도 후보 추가, 기준 충족 시 즉시 장기 기억 승격
- `/뇌추가 @유저 감정=경계 거리감=거리둠 [기억후보]`: 반디의 정서/거리감에 영향을 주는 관계 후보 추가
- `/뇌수정 @유저 [번호] [내용]`: 장기 기억 수정
- `/뇌삭제 @유저 [번호]`: 장기 기억 삭제
- `/메모리파일 [대화/방/투표/뉴스]`: 메모리 JSON 파일 전송
- `/메모리파일`, `/메모리 파일`, `/memoryfile`: 기본 대화 메모리 JSON 파일 전송

멘션 대신 디스코드 ID 또는 저장된 고유 호칭을 사용할 수 있다.

## 데이터 호환성

기존 `brain_notes` 리스트는 로드 시 `long_term_memory`로 마이그레이션된다. 마이그레이션 뒤에도 `brain_notes`는 장기 기억 내용만 담는 호환 캐시로 계속 동기화된다.

잘못된 형태의 `short_term_memory`, `long_term_memory`, `memory_stats`가 저장되어 있어도 로드 시 가능한 범위에서 복구한다. JSON 파일 자체가 깨진 경우 기존 저장소 로직처럼 빈 데이터로 안전하게 로드한다.
